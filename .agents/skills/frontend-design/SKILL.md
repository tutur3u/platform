# Frontend Design

Build working interfaces with a visual direction grounded in the user's purpose,
audience, and existing brand. Choose one coherent direction and carry it through
composition, typography, color, imagery, and interaction. Preserve a supplied design
or established system unless the requested change includes redesigning it.

Focus effort where it changes the experience: clear hierarchy, useful density,
readable copy, recognizable actions, and responsive composition. Distinctive fonts,
asymmetry, texture, and motion are tools, not universal requirements. Check available
assets and dependencies instead of assuming a font or animation package exists.

Implement real behavior and the relevant loading, empty, error, disabled, and success
states. Keep semantic structure, keyboard access, focus visibility, contrast, and
text scaling. Support reduced motion and keep essential content usable if animation
fails. Label mock data; never invent testimonials or product claims as facts.

Match complexity to the brief. Reuse project tokens and components, and split cohesive
responsibilities according to repository limits. Inspect the result at relevant sizes
and fix material visual or interaction defects before reporting completion.
