# CMS renderer

TanStack Start + Void + Vite+ Worker. The synthetic first-site fixture is never a production fallback. Unknown hosts, missing published pointers and unsupported schemas fail closed.

Rex builds locally from the exact reviewed PR head and deploys the emitted `dist/server/wrangler.json`. CI runs afterwards and is not on the deployment path. This lane never deploys. Configure `CMS_DELIVERY_ORIGIN` as the HTTPS origin of the current live external-projects delivery API. The adapter calls `/api/v1/workspaces/{workspaceId}/external-projects/delivery` without preview or authentication parameters. It accepts `publishedPageVersion` with either the service-read `data` snapshot or the Rust `blocks` snapshot and maps both to the shared versioned block contract. An absent binding returns 409; missing snapshots return 404. The live HTTP owner must attach the service-role published-only read from the data contract; the pre-extension live response has no snapshots. Mutable legacy blocks never substitute for a published snapshot.

Configure `CMS_SITES` as a hostname-keyed JSON object. Each site supplies `id`, `workspaceId`, `defaultLocale` and optional `tokens` (`foreground`/`background` hex colors and `font`: serif, sans-serif or monospace). Domain admission belongs to the deployment owner; this is not a self-service domain verification API. Do not route a domain before its ownership is verified.

Entries use full public-path slugs: `home` for `/`, `en` for `/en`, and `en/about` for `/en/about`. Languages remain separate entries. Entry `metadata.description` and `metadata.ogImage` provide page SEO; entry `title` supplies title and OG title. Confirm those paths with the content owner before cutover. Content porting is outside this lane.

The HTML cache key contains site ID, host-derived workspace ID, a random workspace cache epoch, normalized path, locale and immutable version ID. Published delivery responses use a 30-second CDN TTL and HTML uses a 30-second edge TTL. Configure the secret `CMS_PURGE_TOKENS` as a JSON map from site id to a distinct bearer token generated from at least 32 random bytes, encoded as lowercase hex (64–512 characters). There is no global `CMS_PURGE_TOKEN` fallback; absent, malformed, duplicate or short-token configurations refuse purge. A publish hook can POST `{ "scope": "workspace" }` to `/__cms/purge` on the site host with `Authorization: Bearer <token-for-this-site-id>`. Authorization hashes both supplied and expected bearer values to fixed-size SHA-256 digests and compares them with `timingSafeEqual`. The hook registration belongs to the publishing owner and is not wired by this source change. Version-key changes independently avoid serving the old HTML after delivery refreshes.

`bun run build` generates the route tree, then `bun run type-check` validates it. The admitted CI artifact job runs focused renderer/SDK checks and records a bounded emitted-config receipt. PR execution requires a non-draft PR with the `ready-for-ci` label. It has no secret build inputs; any public Supabase build input must come from `vars.PRODUCTION_SUPABASE_URL`. No credentials, live records, custom hostname or production route are included.

The Vite config defines `process.env.NODE_ENV` as `"production"` in the server environment. The Worker startup assertion runs before the server handler loads and refuses any other mode. `workers_dev` and `preview_urls` are false; `start-bridge.config.ts` sets `unknownHost: 'reject'` and the request path enforces that policy against the configured site hosts. CF-2's shared production startup helper replaces the local assertion after its exact head is relayed.

The publisher resolves the purge origin from trusted workspace/site configuration matching a `CMS_SITES` host; `CMS_DELIVERY_ORIGIN` is the backend origin and must not be used as the purge origin. After atomic publish, send only `{scope:"workspace"}` to the verified renderer host. The renderer resolves both site and workspace from that host's `CMS_SITES` entry; it accepts no caller workspace id, path, version or tag.

The publisher stores the matching token for each trusted renderer origin in `CMS_RENDERER_SITES`. The renderer selects only the token keyed by the `CMS_SITES` id resolved from the request host; body fields cannot select a different site. Rotate the matching publisher/renderer token pair together. Never expose the token map in public site JSON or client build variables.

Rotation: each site map value may temporarily be `[oldToken, newToken]`. First add the new token on the renderer and deploy; then deploy the publisher using the new token; finally remove the old renderer token and deploy again. Never reuse a token across sites. Generate tokens using a cryptographically secure random-byte generator; the renderer validates encoding/length and uniqueness, not entropy. Missing site tokens return 401.

The strict purge body contains only `scope: "workspace"`; unknown scopes and extra keys return 400. `CMS_PURGE_RATE_LIMITER` admits up to 30 authenticated purge attempts per site per 60 seconds per Cloudflare location; the native limiter is approximate, not a global hard cap. Rate-limited requests return 429 with Retry-After. A missing/failing limiter returns 503 before any eviction. Each accepted request rotates one site/workspace cache epoch. Previous HTML cache namespaces become unreachable; no content is deleted. This applies within the current Cloudflare location, with 30-second TTLs bounding old HTML entries elsewhere. A missing/evicted epoch creates a fresh random namespace instead of reviving an old one. The rate-limit namespace is `7410004`; Rex verifies account-level namespace uniqueness before deployment. See [Cloudflare rate-limit binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).
