`packages/ai` exposes the Vercel Chat SDK through
`@tuturuuu/ai/chat-sdk`. Use it when a Tuturuuu agent needs to operate across
external channels and internal product surfaces with one normalized thread and
message contract.

The target workflow is:

```txt
Input <-> Omni-channel <-> Tuturuuu Digest <-> Coordinator <-> Internal Apps <-> End users
```

## Package Boundary

Import the Chat SDK boundary from:

```ts
import { createChatSdkRuntime, createChatTools } from "@tuturuuu/ai/chat-sdk";
```

The boundary re-exports Chat SDK core types and the `chat/ai` tool helpers, then
adds Tuturuuu registry helpers for platform and state adapters.

## Runtime Construction

Create a runtime by selecting only the adapters a route or worker owns. Passing
`true` means the adapter should read credentials from its documented
environment variables. Passing an object forwards that object to the adapter
factory.

```ts
const chat = await createChatSdkRuntime({
  userName: "mira",
  adapters: {
    slack: true,
    zalo: {
      botToken: process.env.ZALO_BOT_TOKEN,
      webhookSecret: process.env.ZALO_WEBHOOK_SECRET,
    },
  },
  state: {
    id: "redis",
    config: { url: process.env.REDIS_URL },
  },
});
```

Always choose a production state adapter for deployed bots. Chat SDK state
persists thread subscriptions, webhook dedupe, cache entries, and distributed
locks. The memory adapter is only appropriate for local development and tests.

Cloudflare Durable Objects state is declared in the registry, but its package
imports `cloudflare:workers`; load it only in a Cloudflare Workers runtime.

## Agent Tools

Expose the selected chat runtime to AI SDK calls with Chat SDK tools:

```ts
const tools = createChatTools({
  chat,
  preset: "messenger",
});
```

Use the `reader` preset for analysis-only agents, `messenger` for normal
posting and DM workflows, and `moderator` for destructive operations such as
editing and deleting messages. Keep approval gates enabled by default for
visible writes unless the workflow has an explicit unattended execution policy.

## External Chat Mirror

Apps/web AI agents mirror inbound and outbound Discord/Zalo messages through
server-owned private RPCs. Runtime handlers persist webhook events as soon as
they arrive, then persist any automatic or manual outbound response after the
Chat SDK adapter accepts the post.

When an operator clicks sync in Infrastructure > AI Agents, apps/web creates
the configured Chat SDK runtime, opens the external thread handle, and consumes
recent `thread.messages` when the adapter supports history fetch. Discord can
return recent messages with the right bot scopes. Official Zalo behaves as a
webhook-first adapter, so the mirror is populated by received events. Personal
Zalo channels use the experimental `zca-js` listener and can fetch group chat
history when the personal account session supports it. The personal adapter
also normalizes supported media messages into Chat SDK attachments. The mirror
stores those binaries in the workspace Drive provider, records only private
attachment metadata, and serves authenticated links from the same conversation
API used by native Chat attachments.

## Inbound Attachment Download Limits

External chat mirroring selects at most 10 attachments per message, processes them
sequentially, and accepts at most 25 MiB of actual bytes per attachment. Generic
attachment URL downloads and the concrete personal Zalo media callback enforce the
limit while reading the response stream, including when Content-Length is missing
or understates the body. Existing response-status checks and 30-second fetch
signals remain in place. Empty bodies remain zero-byte attachment data.

In-memory Buffer and Blob sizes are checked before copying or materializing their
bytes. Other injected attachment callbacks are checked after returning; their
internal work and allocations are outside this streamed-reader guarantee.

Personal Zalo attachment downloads retain User-Agent but do not forward channel
cookies to message-selected media URLs. Media that requires those cookies can fail
closed. Provider/channel login remains unchanged. This policy does not establish a
URL allowlist, redirect policy, DNS pinning or general SSRF protection; those need
separate product admission.

Regression coverage lives in `packages/utils/src/read-bounded-response.test.ts`,
`packages/ai/src/chat-sdk/zalo-personal-attachment.test.ts` and
`apps/web/src/lib/ai-agents/external-chat-attachment-limits.test.ts`.

## Teams MSAL Security Compatibility

The root dependency override pins `@azure/msal-node` to 7.1.1 for
GHSA-xcx6-jx8p-x3h5. The direct Microsoft package already uses the patched
major; Teams apps 2.1.1 still requests `^5.6.0`, including through Chat SDK's
Teams adapter 4.43.0. Both are the latest published versions checked for this
upgrade. Remove the override only when the upstream Teams dependency range
resolves a patched MSAL version without it.

Teams' token manager uses confidential client credentials with a tenant
specific authority. It does not enable `instanceAware`, request
`instance_aware`, or use interactive `responseMode`. MSAL 7 removes interactive
response-mode selection and rejects instance-aware confidential clients; retain
those rejections rather than enabling legacy behavior for the adapter.

`scripts/teams-msal-compatibility.test.js` follows the installed Teams ancestry,
requires the patched version, and exercises the actual Teams token manager and
MSAL client-credentials exchange using a fixture network transport. It also
checks the interactive and instance-aware rejection boundaries. Run it with
`node --test scripts/teams-msal-compatibility.test.js` after dependency changes.
These fixtures do not establish hosted Azure credential acceptance, managed
identity, or federated identity behavior. Require exact-commit CI and independent
security review before integration.

Upstream references: [MSAL advisory](https://github.com/AzureAD/microsoft-authentication-library-for-js/security/advisories/GHSA-xcx6-jx8p-x3h5)
and [MSAL v7 migration guide](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-node/docs/v7-migration.md).
