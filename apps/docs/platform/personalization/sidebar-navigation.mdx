## Default layout

The dashboard sidebar always keeps **Dashboard** in the root navigation. By default, the root navigation then shows **Tasks**, **Calendar**, and **Finance**.

All other eligible top-level tools are placed under **More tools**. More tools is grouped into durable sections:

- **Work tools**: Habits, Whiteboards, Track, Drive, Forms, Documents
- **AI**: Mind, Hive, Chat, AI Lab
- **Operations**: Workforce, Users, Inventory
- **Utilities**: QR Generator, Google Workspace, Meet, Polls, Mail, Education, Link Shortener

Dashboard is separated from the main root tools. **Settings** is pinned to the bottom of the sidebar, below More tools and Archived (including when Archived is promoted to the root sidebar).

## Managing layout

Users manage start-page navigation, sidebar behavior, sidebar layout, and recent-history visibility from **Settings → Preferences → Navigation & Sidebar**.

On desktop, **Expand on hover** keeps the sidebar open while a popover, menu,
or dialog opened from it is active. After you dismiss the last overlay, the
sidebar collapses if the pointer is outside it. This applies to Web, Workspace,
and satellite dashboards that offer hover expansion.

The collapsed rail, and the resting rail of **Expand on hover**, show icons
only by default (decided 2026-11-22). Each item's tooltip and accessible name
carry its full name. **Settings → Sidebar → Show navigation labels** (off by
default) brings back a one-line caption under each icon, **Settings**
included; long names truncate. The choice is saved to the account (user config
`SIDEBAR_NAV_LABELS`), so every app's sidebar follows it, and each device
applies its last value before the first paint (`data-nav-labels="shown"` on
`<html>`), so the rail never flips after loading. The rail stays 4rem wide either
way. This applies to Web, Workspace, and satellite dashboards that render items
through the shared `NavLink`; Colab draws its own rail items and stays icon-only.
Meet exposes the same preference and sidebar modes under **Settings → Sidebar**.

In the sidebar footer, **Feedback** is a compact icon button on the same row as
**Settings**, with a tooltip and an accessible name; Discord, when configured,
sits beside it the same way, and **Upgrade**, when offered, keeps its label in
the expanded sidebar. In the collapsed rail they stack under Settings as icon
buttons. The account and notification controls are unchanged. Coverage:
`packages/ui/src/components/ui/custom/nav-link.test.tsx`,
`packages/satellite/src/components/sidebar-settings-button.test.tsx`,
`structure.test.tsx` and `satellite-shell.test.tsx` (footer row),
`experimental-ui-sync.test.tsx` and `sorbet-pre-paint.test.tsx` (the label
choice), and the layout-shift harness in
[Web design system](/build/development-tools/web-design-system#hover-expand-sidebar).

## Sidebar modes

**Settings → Sidebar → Sidebar Behavior** offers four modes on desktop. The
choice follows the account across browsers unless **Local Override** is on.

| Mode | At rest | Opening the full sidebar |
| --- | --- | --- |
| Expanded | Full sidebar, in the page flow | Already open |
| Collapsed | Icon rail | The size toggle |
| Hover | Icon rail | Hover the rail; it opens over the page |
| Minimal | The Tuturuuu logo only | Hover, keyboard focus or tap the logo |

**Minimal** (decided 2026-11-22) is the mode for the most room: the rail, its
border and the account controls are gone and only the logo floats at the top
left. The logo sits on a 48px rounded-square button (the theme's row radius, so
Sorbet's Corners option scales it; never a pill) with 10px around the logo, 8px
from the top and left edges. The button is a floating control, not a docked
rail: it keeps the same position, size and look whether the panel is open or
closed, and the open panel reserves its square in the header. Page content
starts 8px past the button (a 4rem gutter derived from the button's size and
inset) at every desktop width, and never moves when the panel opens or closes
(decided 2026-11-23).

- **Hover**: resting the pointer on the logo or anywhere along the left edge
  for 120 ms opens the sidebar as a floating panel over the page. A pointer
  that only crosses the edge opens nothing. Leaving closes it after 240 ms, so
  slipping off and back keeps it open.
- **Keyboard**: focusing the logo opens the panel and leaves focus on the logo;
  the panel draws the focus ring meanwhile. Tab moves through the panel and
  loops inside it. Escape closes it and returns focus to the logo; Enter or
  Space on the logo toggles it. Picking a destination closes the panel.
- **Touch**: a tap on the logo opens the panel; a tap outside, or on a
  destination, closes it.
- **Overlays**: a menu, dialog or popover opened from the panel keeps it open
  and takes the first Escape.
- **Motion**: the panel and its labels fade in and out in place over 150 ms;
  nothing slides or scales. The panel appears at once when reduced motion is
  preferred. **Hover** mode fades the same way, and its rail icons and logo
  keep their exact position while the labels fade in beside them
  (decided 2026-11-23). With **Show navigation labels** on, rail captions make
  rail rows taller than panel rows, so the icon column does not line up then.
- **Phones**: the top bar and drawer are the same as in every other mode.

Minimal takes the place of a mode named Hidden, which removed the sidebar and
left no visible way back. A stored `hidden` value reads as `minimal` everywhere
(the behavior cookie, the account preference and the assistant's `set_sidebar`
tool). The cookie is rewritten on the next visit. Selecting a mode saves its
current value to the account. Cmd/Ctrl+Alt+B switches to Minimal and
Cmd/Ctrl+B switches from it to Collapsed. The tasks board's **Minimal sidebar**
action and the account menu use the same mode.

In satellite Settings, the sidebar keeps its current layout until the dialog
closes. Focus returns to the control that opened Settings or to the reveal logo
if the selected mode replaced that control.

Scope: Web, Workspace, Colab and every satellite sidebar. Exception: Nova has a
single fixed sidebar and no modes. Coverage: `sidebar-behavior.test.ts`,
`structure-minimal.test.tsx`, `use-sidebar-rail-underlay.test.tsx`, and the
cookie and account-preference cases in `sidebar-context.test.tsx` and
`sidebar-remote-behavior-bridge.test.tsx` under
`packages/ui/src/components/ui/custom/`. The Chromium layout-shift harness
(`scripts/ci/sidebar-layout-shift.mjs`, both modes) asserts zero layout shift,
the fixed logo and icon positions, the fade-only reveal and the content
clearance at 768 to 1920px.

## Workspace switcher

The sidebar always shows a dropdown-style row under the app name: the current
workspace's avatar and name (truncated, with the full name in a tooltip) and a
chevron (decided 2026-11-23). Clicking it, or pressing Cmd+Shift+K
(Ctrl+Shift+K), opens the **Select workspace** dialog; workspaces are chosen
there, and no menu or list opens in the sidebar. A pending-invitation count
shows beside the name and is announced as the row's description. The row has no
show/hide control. This applies to Web, Workspace and every satellite sidebar.

On desktop, the collapsed rail shows the same row as the avatar alone, at the
same position as in the expanded panel, with a tooltip (workspace name and
"Switch workspace"), an accessible name and a dot for pending invitations.
Hovering the rail restores the name without reopening the dialog. Minimal mode
shows the selector only while the panel is open. The settings breadcrumb and the
account menu show the workspace name and plan. Coverage:
`workspace-select-trigger.test.tsx` and the sidebar case in
`workspace-select-invitations.test.tsx` under
`packages/ui/src/components/ui/custom/__tests__/`.

## Account menu

Every app opens the same account menu from the avatar (`SatelliteUserMenu` with
`SatelliteUserMenuItems` in `@tuturuuu/ui`), with this order:

1. Name and email. In Web and Workspace the name opens profile settings.
2. Workspace switcher, where the app has workspaces.
3. Public profile, **Settings**, then the app's own actions: the command palette
   in Web and Workspace, **Invite members** in Workspace, and Nova's Home,
   Profile, Challenges and Leaderboard.
4. **Sidebar**, **Language** and **Theme**.
5. **Upgrade**, **Feedback**, **Notifications** (with the unread count) and
   **Discord**, each shown only where the app offers it. Notifications sit
   directly below Feedback.
6. **Switch Account**: every saved account with its avatar, or initials when it
   has none, a check on the current account, **Remove account** and **Manage
   Accounts**. Web and Workspace open Manage Accounts in their settings dialog;
   satellites open it on tuturuuu.com.
7. **Logout**.

The menu has no Dashboard link; the app switcher in the sidebar header reaches
other apps. Coverage: `satellite-user-menu-items.test.tsx` and
`satellite-account-switcher-avatars.test.tsx` under
`packages/ui/src/components/ui/custom/`, and
`apps/web/src/components/settings/settings-dialog-shortcuts.test.tsx`.

## Hover lock

In expand-on-hover, the panel stays open while any overlay opened from it is
open, including one that replaces another: the account menu, its Sidebar,
Language and Theme submenus, Notifications, Feedback and the workspace dialog.
Portalled content counts as inside the sidebar. A closing overlay keeps the pin
for 400ms so the next one can mount (the account menu hands off to the
Notifications popover and to dialogs), and the panel collapses only after every
overlay has closed and the pointer is outside. Coverage:
`notification-popover.test.tsx` (account menu to Notifications),
`structure.test.tsx` (hand-off between overlays) and the Chromium harness.

## Icon alignment across rail and panel

Every icon keeps one x position whether the sidebar is collapsed, resting in
expand-on-hover, or expanded (decided 2026-11-23). The shell defines
`--sidebar-rail-slot` (the collapsed width minus the 1px edge border and the
0.5rem gutters); navigation rows, the workspace avatar, the account avatar, the
footer actions and the brand logo all center their icon in that slot, and rows
use identical left padding in both states, so expanding only reveals labels and
trailing controls.

The footer is two items: Settings and the account avatar, at the same x and y
in the rail and the panel (decided 2026-11-23). Expanding reveals the Settings
label and the name and email beside the avatar. Notifications, Upgrade, Discord
and Feedback have no footer controls: the avatar shows the unread count as a
badge, includes it in its accessible name, and its menu lists Notifications
(with the count; it opens the notifications popover beside the avatar, with focus
returning to the avatar on close) first, then Upgrade, Feedback and Discord
after the preference submenus. Feedback appears once.
The same menu serves the phone top bar. An app that passes no account slot keeps
its combined actions row.

Scope: Web, Workspace, Colab, Nova and every satellite sidebar, in Sorbet/Minimal
mode too. Nova keeps its own navigation rows, and the Git sidebar's footer is its
admin link. Known exception: when **Show navigation labels** is on, the rail adds
a caption under each icon, so rows are taller than in the panel. Coverage: the
Chromium harness (`scripts/ci/sidebar-layout-shift.mjs`) measures the logo,
navigation icons, workspace avatar, Settings and the account avatar in the rail
and the open panel at 1024, 1440 and 1920px in both themes and fails when any x
or y differs by more than 0.01px; it also checks the avatar badge and accessible
name, the menu items, the notifications popover and focus return.
`structure.test.tsx` and `satellite-shell.test.tsx` cover the footer slots and
the account hub.

## Preference precedence

Sidebar layout preferences use a hybrid model:

1. Workspace override: `user_workspace_configs.SIDEBAR_NAVIGATION_LAYOUT`
2. Account default: `user_configs.SIDEBAR_NAVIGATION_LAYOUT`
3. Authored default layout

The saved layout stores three ordered id lists:

- `root`: first-level tools shown directly in the sidebar
- `more`: first-level tools shown inside More tools
- `hidden`: first-level tools archived from normal sidebar rendering

Unknown or stale ids are ignored when the layout is applied and are dropped the next time the user saves preferences.

## Quick actions

First-level navigation items expose compact hover actions in the sidebar:

- **Pin** moves an item from More tools to the root sidebar.
- **Unpin** moves an item from the root sidebar to More tools.
- **Archive** hides an item from normal sidebar rendering.

Pin, unpin, and archive also appear on tier-gated items that render grayed out in the sidebar. Saving layout preferences does not grant access to unavailable tools.

Dashboard and Settings are locked and cannot be pinned, unpinned, or archived.

Archived items appear in a compact **Archived** dropdown at the bottom of **More tools**. More tools remains visible when archived items exist alongside other visible More tools children.

When every normal More tools child is hidden or unavailable and **Archived** is the only remaining visible child, structure promotion lifts **Archived** to the root sidebar instead of leaving an empty More tools wrapper. Selecting an archived item from that dropdown (or the root Archived entry) restores it to its previous root or More tools placement.

## Visibility rules

Preferences never bypass authorization, feature flags, production gates, root-workspace restrictions, or tier visibility. If a tool is unavailable for the current user or workspace, placing it in root navigation does not make it appear.

Hidden tools remain directly routable. When the current route matches a hidden tool or one of its descendants, the sidebar reveals that item only for the current route and marks it as an active hidden item. This contextual reveal is not saved back into the preference config.

## Recent history

Recent sidebar navigation history is controlled by `user_configs.SIDEBAR_RECENT_NAVIGATION_ENABLED`.

The default is **off**. When disabled, the sidebar does not render recent navigation history and does not record recent visits.
