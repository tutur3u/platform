Shortener (`shortener.tuturuuu.com`, `apps/shortener`) is the redirect runtime.
Workspace link-management and analytics pages remain in Web under
`/{wsId}/link-shortener` where registered. The service and the management UI
have separate responsibilities.

## Follow a short link

A `/{slug}` request resolves through the configured redirect implementation.
The destination and current access/validity checks determine the result.
Do not assume a short link is a public content page, an authentication bypass,
or a published copy of its target. Inspect the destination's own access rules.

### Redirect rules

These rules apply to every Shortener host (`ttr.gg` and its configured aliases)
on the native Start + Void runtime:

- **Lookup.** Generated slugs and custom aliases share one exact,
  case-sensitive lookup of the stored slug.
- **Redirect.** A found link with a valid destination answers `307` with
  `Location` set to the stored target, byte for byte. The URL parser serializes
  the target only when it contains spaces or non-ASCII characters. The short
  link's own query is not appended, as in the legacy page. The click row is
  written before the redirect is returned, and an analytics failure never blocks
  the redirect.
- **Destination validation.** A stored target that does not parse, or that
  uses `javascript:`, `data:` or `vbscript:`, renders the invalid-destination
  page and records no click. Script schemes were previously parseable; refusing
  them is an intentional tightening.
- **Password links.** These render the password form with the hint, never the
  destination. `POST /api/verify` keeps its legacy statuses (`400`, `403`, `404`,
  `500`) and records a click only after a correct password. The browser leaves
  only for a navigable destination.
- **Missing links.** A missing slug renders the not-found page with `200`, as
  before. Deeper paths return `404`.
- **Aliases.** Alias hosts redirect to `ttr.gg`, preserving the path and the
  raw query, duplicate keys included. `www.ttr.gg` uses `308`; the other five
  aliases use `307`.
- **Analytics.** On Cloudflare, click geolocation comes from the trusted
  request metadata and the client IP from `CF-Connecting-IP`, while
  `vercel_region` and `vercel_id` stay null. Vercel Web Analytics is not loaded
  on the native runtime.

Regression coverage lives in `apps/shortener/src/link/link.test.ts` and
`apps/shortener/src/native/shortener-request.test.ts`. The emitted Worker suite,
`apps/shortener/cloudflare/native-built-worker.test.mjs`, runs in CI. The cutover
and rollback profile is in
[Shortener on Start + Void](/build/devops/shortener-start-void).

## Manage links

Use the workspace management flow to create/manage supported links and inspect
available analytics. Analytics represent the events the implementation records;
they are not proof of unique people, conversions, or the destination's state.
Workspace permissions still govern management and analytics.

## Search policy

The redirect host is noindex and advertises no sitemap. Public landing pages
should be indexed on their canonical destination host instead of accumulating
short-link copies in search. The HTTP noindex policy also applies to API and
error responses.

See [Shortener routes](/reference/repository/routes/shortener) and the
[Web route inventory](/reference/repository/catalog) for the exact source entry
points. [Search indexing](/platform/features/search-indexing) explains why
redirect execution and public content discovery are separate concerns.
