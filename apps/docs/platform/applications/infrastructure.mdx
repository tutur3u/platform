Infrastructure (`infrastructure.tuturuuu.com`, `apps/infrastructure`) is the
privileged operational console. It exposes workspace/account controls,
monitoring, configuration, and selected provider gateways. The existence of a
console route never bypasses its operator eligibility and permission checks.

## Operational areas

- Workspace/user administration, internal accounts, external-app registration,
  account benefits, and app coordination.
- AI policy, agents, credits, rate limits, abuse intelligence/events, blocked
  IPs, recovery/appeals, and entity-creation limits.
- Email queues/templates/audit, push notifications, and Calendar sync.
- Mobile/desktop deployment records, versions, translations, holidays,
  timezones, Devboxes, and migration diagnostics.
- Monitoring for requests, logs, analytics, projects, deployments, rollouts,
  resources, and retained cron/control surfaces.

The [route reference](/reference/repository/catalog) lists every current
Infrastructure entry point in its numbered source pages. Feature-specific
operating rules remain in [DevOps](/build/devops/overview) and
[Commercial controls](/platform/features/commercial-controls).

## Current schedulers

Hosted Calendar provider sync and smart scheduling run through Infrastructure's
Vercel schedule and authenticated Calendar gateway. The
[Cloudflare Cron Control Worker](/build/devops/cloudflare-cron-control) owns
immediate notification recovery. The Docker cron runner is retired. Retained
Docker controls and stale local heartbeat records do not establish the health
of either hosted scheduler.

Use the [active runtime map](/build/devops/active-runtime) to trace a job from
scheduler to gateway to processor. Verify recent domain results as well as a
successful scheduler invocation.

## Privacy and change control

Console pages and APIs are noindex, including errors, auth redirects, and
non-HTML responses covered by the app policy. Search controls supplement actor,
workspace, permission, token, and storage checks. Runtime logs use native
`console.*` with the original severity; operational log-drain services are
separate boundaries.

A configuration edit, deploy action, external registration, or production write
requires its own authorized workflow. Reading a runbook or recalling a private
record is not authority to execute it.

## Employee SQL transport qualification

Employee creation remains unavailable until its protected SQL supplier and
project readiness are independently qualified. The fixed transport prototype
accepts only preflight, finalize and activation-confirm operations. Each request
owns one terminable child and TLS connection; no shared pool, caller SQL,
account password or inherited database configuration enters that boundary.

The executor is shared through the server-only
`@tuturuuu/inventory-core/infrastructure/employee-sql/process` leaf; only this
leaf's dependency closure is framework-free. Original Infrastructure entry
points remain compatibility entries, while the canonical raw worker and protocol
are colocated under `packages/inventory-core/src/lib/infrastructure/employee-sql/`.
Before binding the Web supplier, verify that the compiled route's `.nft.json`
trace and resolved `fork()` target load the canonical worker, protocol, and
runtime dependencies. Relocation requires qualification of the exact source and
build with refreshed signed attestations, even when raw worker/protocol hashes
are unchanged.

The parent requires external Ed25519-signed project and execution attestations,
including the exact worker and protocol hashes. Missing bindings deny before
spawning. Ordered, same-connection catalog checkpoints validate the role, cluster,
ledger, function bodies and effective privileges before effects and COMMIT.
The parent records an uncertain commit before authorizing COMMIT; lost commit
acknowledgement never authorizes a blind retry or replacement account ID.

The process requests cancellation at 13 seconds and kills only its owned child
at 14.5 seconds, reserving cleanup time within the qualification profile's
15-second budget. It waits for actual child closure. Client process/TCP drain
controls do not establish server transaction rollback or row-lock release.
Before wiring the supplier, qualify delayed connection/query/lock/COMMIT cases
against disposable PostgreSQL, verify backend and lock drain, and verify the
static worker/protocol assets in the exact hosted Next build and file trace.
Source tests, schema assertions and signed synthetic fixtures cannot replace
those gates or activate account creation.
