## Primary action

Each Finance list puts its most-used action in the floating dock's priority
slot, because people add records far more often than they search:

| Screen | Primary action |
| --- | --- |
| Overview | New transaction |
| Transactions | New transaction |
| Wallet | New transaction in that wallet |
| Budgets | New budget |
| Wallets | New wallet |

Search is a top-bar icon on Transactions and Wallets (Overview's search opens
Transactions in search). The action is only offered with the matching
permission. Where the dock has no room for it (narrow phones with every
destination shown), the shell shows it as a filled top-bar button instead.

## Destinations

The dock holds Overview, Transactions, Budgets and Wallets; More opens
Categories, Checkpoints (the all-wallet check), Analytics, Invoices, Reports,
Recurring transactions, Debts & loans and Promotions, and reserves the next
entry for the bill-splitting module's Split bills. Overview keeps balances, the
month and recent activity only. Invoices, Reports and Recurring transactions
open as sheets from any Finance destination and keep their deep links
(`/finance/invoices`, `/finance/reports`, `/finance/recurring`), which open the
sheet and then land on Overview. Invoices needs `view_invoices`; Reports needs
`view_finance_stats` and a wallet, and says so when there is none. The menu
and the deep links apply the same grants; while grants load, More lists every
tool and the chosen one waits up to 15 seconds for them in the workspace it was
chosen in, then explains a missing grant or a failed load. A deep link waits
once from when it opens and then lands on Overview; a workspace switch before
its tool opens restarts it for the current workspace, and reads already
started for the earlier workspace are dropped. Reports opens without exchange rates when they are unavailable; only a
cross-wallet report needs them. A failed
load shows a toast instead of doing nothing, and any workspace switch while the
sheet's data loads drops it. Finance has no separate Manage
page: creating a wallet belongs to Wallets, and old `/finance/manage` links
open Wallets. Coverage: `finance_manage_redirect_test.dart`,
`finance_section_reset_test.dart`, `finance_overview_test.dart`,
`finance_more_actions_test.dart` and
`app_registry_test.dart`.

## Periods

Transactions and a wallet page pin a period selector: previous and next
(never past today) around one title that names the granularity above the
period. The title opens the granularity sheet, and each choice shows the
period it lands on: other granularities keep the visible period's start,
while choosing the current one again returns to today's period.
Transactions offers Day, Week, Month, Year, a custom date range and All
time, which search uses. Wallet pages and reports chart several buckets per
period, so they offer Week, Month and Year. Both open on the current month.
Weeks start on Monday. The wallet, category, tag and creator chips share the
kind pills' fill and clip only at the screen edge. Finance managers can also
filter Transactions by tag. `finance_period_selector_test.dart` covers the
granularity anchors, the Next limit and the centred label.

## Empty transactions

The empty message follows what hides the rows; the period alone never counts
as a filter:

- Nothing in the period: "No transactions in {period}" with Add first
  transaction.
- Kind, category, tag, creator or wallet filters hide every row: "No matching
  transactions" with Clear filters, which keeps the period.
- A search query matches nothing: "No results for {query}" with Clear search.

## Wallet page

A balance card (with a workspace-currency estimate for foreign wallets and the
credit limit for credit wallets) offers Transfer and Edit. Below the balance, Reconcile opens the wallet's
balance review and the checkpoint timeline opens its recorded checks. Below
the pinned period bar, the period's income, expense and net
keep their labels on one line at any supported width and text size; amounts
shrink to fit rather than clip, and the figures stack when three columns would
be too narrow. A daily in/out chart (monthly for a year) appears once every
row of the period is loaded. Transactions follow, grouped by day with each
day's net.

## Wallet role access

People with `manage_workspace_roles` open Role access from a wallet's top bar.
It lists each workspace role that sees the wallet with its history window
(last day to last year, or a custom 1 to 365 days). They grant a role that
has no access yet, change a window by tapping its row, and revoke after
confirming. Writes need a connection; the list reads through the offline
cache. Coverage: `wallet_role_access_test.dart`.

## Wallet reconciliation

Enter the observed balance to preview the signed variance against the wallet
ledger. Save checkpoint records a checkpoint without changing
transactions. When a check uses a different date or time, its saved details
show the server-calculated historical variance.

Open a checkpoint in the timeline to compare the observed and ledger balances.
Wallet editors with access to the checkpoint can mark it reviewed or reopen
it on web or mobile. Changes to the observed amount or time reopen the
checkpoint. Review status is independent of the variance and updates across
devices when the timeline refreshes.
People with transaction-create permission can post a non-reporting adjustment
for the checkpoint or for an unresolved interval between two checks. The server
calculates the adjustment from the current ledger and skips it when the
difference is zero. Wallet-update permission controls recording, editing and
deleting checks. Each check uses its wallet's currency.

All-wallet check records several observations at one time for every active
wallet. Each entered balance previews the wallet's ledger balance and the
variance it would record, and the amount-visibility control masks variances
as well as balances. The focused `wallet_checkpoint_ui_test.dart` covers
signed balance inputs, variance direction and light and dark renders.

Variance tones are shared by the checkpoint list, the review sheet and the
timeline: balanced is success, a shortfall (observed below the ledger) is
destructive and a surplus is a warning, because both differences still need
an explanation.

The Checkpoints list filters active wallets by All, Mismatched and Unchecked
with counts, and sorts by name, largest variance or least recently checked.
Each row opens that wallet's reconciliation view. People with wallet-create
permission add a wallet from the dock without leaving Checkpoints. Wallet
editors swipe a row to archive it and can Undo from the toast; the Archived
filter, shown while any wallet is archived, lists them and swipes to
restore. Archiving sets the wallet's `archived_at` and keeps its balance,
transactions and checkpoints. Only mobile Checkpoints and its all-wallet
check hide archived wallets; other wallet pickers and web Finance still list
them. `checkpoint_wallets_test.dart` and `finance_checkpoints_page_test.dart`
cover the filters, sorting, archive overrides and Undo.

## Analytics

Analytics (`/finance/analytics`) needs `view_finance_stats` and shows the
workspace in its currency for a week, month or year (current month by
default) from the server's chart endpoints. The hero shows the closing
balance with the opening balance and net change. Income, expense and net
follow with one bar pair per day (per month for a year), then the balance
trend and expense or income totals per category with each one's share.
Category days follow the device time zone. Hidden amounts hide the charts
and shares. Workspace `/api/workspaces/{id}/finance/*` requests go to the
Finance origin. Requests send `includeConfidential` explicitly, and the chart
routes treat an omitted value as `true`. A failed load names the cause with
Retry: a rejected request, an expired session, an unresponsive service, or
being offline. Coverage: `finance_analytics_page_test.dart`,
`finance_analytics_repository_test.dart` and the chart route tests in
`apps/finance`.

## Promotions

Promotions (`/finance/promotions`) lists invoice discount codes for people
with `create_invoices` or `view_inventory`: name, code, percentage or fixed
discount, and usage against any limit (Used up once reached). Inventory owns
codes, so `create_inventory`, `update_inventory` and `delete_inventory` gate
create, edit and delete; the form checks that a percentage stays within
100% and that a usage limit is a whole number. The invoice editor offers
promotions that still have uses and sends the chosen `promotion_id`; the
server computes the discount. Workspace `/api/v1/workspaces/{id}/promotions`
requests go to the Finance origin, which forwards writes to Inventory.
Coverage: `finance_promotions_page_test.dart`.

## Debts and loans

Debts & loans (`/finance/debts`) leads with the net position: what others
owe the workspace minus what it owes, with both totals and their active
counts. A status chooser (Active by default, or any status) and Debts /
Loans pills with counts filter the list, which shows overdue entries first,
then the nearest due date. Each row shows the counterparty, due date (Overdue
in the destructive tone), repayment progress and remaining balance. Rows open
the repayment overview and terms. People with `manage_finance` create and
edit entries (type, name, counterparty, principal and currency, annual rate
with simple or compound interest, start and due dates, wallet and notes),
mark one paid, set any status and delete after confirming. The server derives
every balance, so writes need a connection; the list and summary read through
the offline cache. Linked repayment transactions are not listed on web or
mobile. Coverage: `debts_page_test.dart`.

## Budgets

Each budget shows its health (on track, near limit, over), what is left and
what can still be spent per remaining day, counting today. Tapping a budget
opens its details; Edit is offered with budget permission.

## Recurring transactions

More opens recurring transactions, with each rule's frequency, wallet and
next scheduled date. Finance managers can create, edit or delete rules. Use a
negative amount for an expense and a positive amount for income. A rule uses
the selected wallet's currency and can end on a date.

The Recurring sheet opens with the next 30 days: active rules due from today,
soonest first, with expected money in and out when every run shares one
currency. All rules follow. Overview shows people with `manage_finance` one
banner for budgets over or close to their limit, from the server's budget
status: destructive while any is over, a warning otherwise, naming up to three
and linking to Budgets. Coverage: `finance_budget_alerts_test.dart` and
`recurring_transactions_test.dart`.

## Invoices and subscriptions

Open Invoices from More. Search by customer, open an invoice to edit
its description or notes, and create invoices from catalog products. Each line
uses the selected unit and warehouse. The server checks the prices and issues
the invoice.

Subscriptions lists outstanding group payments. Pick an entry to collect a
payment for a month and select the number of months covered. Finance
permissions control access, creation, editing, and deletion. Mobile keeps
ambiguous saves from being submitted again until the invoice list can be
checked.

`finance_invoices_test.dart` covers opening the list, editing an invoice, and
selecting an outstanding subscription.

## Reports

Open Reports from More and choose a wallet and calendar period. The
report shows income, expense, cumulative net movement from the start of the
period, and category totals in the selected wallet's currency. Transfers and
transactions excluded from reports are omitted. Amount masking hides the
charts and all financial figures. For a large report, choose a shorter period.

`finance_report_test.dart` covers period and category totals.

Cross-wallet reports include reporting-enabled wallets and use the latest
available exchange rates to estimate totals in the workspace currency. A
missing exchange rate stops the report. Invoice reports show counts by
creator and each wallet's amount in its own currency.

## Credit wallets

Credit summary shows availability, utilization, activity, statement balance,
and payment dates calculated by Finance. Its payment action starts a transfer
into the credit wallet. Purchases and refunds open the transaction composer
with the expense or income mode selected.

## Wallet interest

Open Interest tracking in a wallet to view accruals, projections, historical
interest, and rate history. Wallet editors can opt in to MoMo or ZaloPay
tracking when Experimental Finance is on for the workspace. Existing
configurations remain visible and editable with the matching wallet permissions.
The selected projection period draws projected cumulative interest as a
sparkline, and deposits that have not started earning list their deposit date,
amount and the day interest begins. Both hide with amounts. Coverage:
`finance_interest_render_test.dart`.

## Transaction filters

The creator filter matches both workspace and platform creator records. A
custom date range includes the selected end date in the device's local time.
Search and CSV export use the selected creator and custom date range.

## Invoice workflows

Start a subscription for a customer and eligible groups on the Subscriptions
tab, then select the wallet and add invoice lines. Invoice editors with wallet
reassignment permission can change the linked wallet. A currency change
requires confirmation because the invoice retains its numeric amount.

An opened invoice shows a receipt: customer, date, wallet and content, each
line with its quantity, unit and price, the subtotal, the signed adjustment
(Discount with the applied promotion codes when negative) and the total.
Share invoice sends that receipt as a PNG, as web exports one. The receipt
comes from `GET /api/v1/workspaces/{id}/finance/invoices/{invoiceId}`, which
needs `view_invoices`. Coverage: `finance_invoice_receipt_test.dart` and the
Finance route's `detail.test.ts`.

Invoice history requires workspace audit permission. Recovery uses the stored
snapshot and requires the same create and delete permissions on web and mobile.
Fee locks support drafting from configured tuition lines, editing quantities,
locking a version, and reopening with a reason. The web app includes bulk
operations, notice templates, and custom fee lines.

## Import and export

Finance managers can import Money Lover files from Transactions. Choose the
delimiter and file, review the row count, and confirm. The file limit is 5 MB
and 10,000 transactions. Each file wallet must have a uniquely named wallet in
the workspace with the same currency. The receipt reports how many rows the server imported.
Check the ledger if the server did not confirm an import before trying again.

The export action shares a CSV for the current transaction search and filters.
Exports require Finance data export permission. The all-transactions view can
include transfers alongside other entries. Narrow a large export by date.

Invoice exports use the invoice or pending-subscription search and require
Finance data export permission. Share a CSV or Excel file for up to 5,000
matching rows. If this limit is reached, narrow the search.

## Hidden amounts

The eye toggle masks every figure on these screens, including balances,
totals, day nets, budget meters and per-day allowances. The wallet chart is
omitted while amounts are hidden, since bar heights would reveal relative
sizes.

Regression coverage: `finance_redesign_test.dart` (label fit at 320 dp and
1.3x text, empty-state variants, wallet masking, period and budget-pace
rules), `finance_accessibility_test.dart` (create in the dock, search in the
top bar, masking on every screen) and the Linux goldens in
`finance_goldens_test.dart`.

## Parity with web Finance

Compare the native mini app with the standalone web Finance dashboard in
`apps/finance/src/app/[locale]/(dashboard)/[wsId]`, its shared UI in
`packages/ui/src/components/ui/finance`, and the mounted APIs in
`apps/finance/src/app/api` and `packages/apis/src/finance`. The entry in
`apps/web` links to standalone Finance.

| Feature | Web Finance | Mobile Finance |
| --- | --- | --- |
| Overview | Balances, income and expense, category and balance trends | Balances, workspace-currency estimate, monthly cash-flow chart and recent activity |
| Wallets | List, detail, create, edit, delete, credit and interest tools | List, detail, create, edit, delete, interest tracking, and credit summary, charge, payment and refund actions |
| Transactions | List, detail, create, edit, delete, attachments, confidentiality and reporting preferences | Core transaction lifecycle, attachments, confidentiality and reporting preferences |
| Categories | Create, edit, delete and migrate | Create, edit and delete. Migration is open |
| Tags | Manage workspace tags and assign them to transactions | Create, edit and delete tags in Categories. Assign tags to transactions |
| Budgets | Create, edit, delete and track category budgets | Create, edit, delete, detail, status and daily spending pace |
| Bill splits (flagged) | Quick and detailed expense editors, payment reports, confirmation, signed-in and opt-in public sharing, bank details and reminders | Single-expense editor with equal, exact, and percentage shares, server preview, payment reports, confirmation, receipts, and copyable signed-in links for split, participant, and settlement views |
| Transfers | Linked wallet entries with source and destination amounts | Create and edit transfers, including cross-currency amounts. Linked entries collapse in activity |
| Recurring transactions | Schedule and manage recurring rules and view upcoming entries | List, create, edit and delete rules. Next dates appear in the list |
| Invoices | Create and manage invoices, subscriptions, fee locks and reporting | Search, create, edit, delete, collect and set up subscriptions, change wallets, restore eligible deleted invoices, and manage fee lock drafts and revisions |
| Reports and charts | Balance trend, cash flow, category breakdown and invoice analytics | Wallet and cross-wallet cash flow, cumulative movement, category totals, and invoice totals by wallet and creator |
| Wallet checkpoints | Record observed balances, batch check, history and transaction adjustments | Inline wallet review and timeline, checkpoint and interval adjustments, compact all-wallet check, filters, sorting, quick wallet creation and archive with Undo. Review status is shared with web; archiving is mobile-only |
| Multi-currency | Wallet currencies, exchange rates and converted workspace totals | Wallet currencies, exchange rates, converted workspace totals and amount masking |
| Filters and search | Text search plus wallet, category, tag, creator, date and transaction type filters | Text search, wallet, category, tag, creator, type and custom date ranges |
| Exports and imports | Transaction export, Money Lover import and invoice spreadsheet exports | Transaction CSV export, Money Lover import, and CSV or Excel exports for created and pending invoices |
| Debts and loans | List, summary, create, edit, status and delete | Same, with the net position hero and overdue-first ordering |
| Promotions | Create, edit, delete and apply to invoices | Same, with usage meters |
| Wallet role access | Grant, change window and revoke per wallet | Same, from the wallet top bar |
| Inventory reconciliation | Dedicated web workflow | Open |

Mobile requests use the Finance repository and its bearer-authenticated endpoint
mappings. Verify routes and response contracts before adding a new client call.
