## Conversation browsing

Mobile Chat retains the shared app shell and navigation while compact screens
switch between the conversation list and a selected thread. Wide screens keep
both panes visible. The list remains scrollable with tall filter content.

Conversation pages load automatically when the remaining scroll distance falls
below three quarters of the viewport, including when the first page cannot fill
the screen. Only one automatic request is made for an unchanged scoped list;
failed or empty pages retain a manual Load more action rather than retrying in a
loop. The manual action also remains available when filters show no rows.

Pagination results and failures from an older workspace or refresh generation
cannot publish into the current list. Pending local rows continue to use the
existing scoped Chat collection overlay.

## Composer

Attachments use the adaptive sheet shared by compact and expanded mobile
surfaces. Send remains disabled while a message or attachment upload is in
flight, and the icon exposes a localized tooltip. This changes neither message
transport nor attachment permissions; live device and production verification
are still required for delivery.

Regression coverage: `chat_conversation_layout_test.dart`,
`chat_pagination_scope_test.dart`, and `chat_thread_layout_test.dart` in
`apps/mobile/test/features/chat`.


### Assistant settings route chrome

Mira quick settings and the Assistant entry in general Settings open the same
account- and workspace-scoped editor. Because this imperative route covers the
app shell, it owns a branded Assistant Settings header, top safe area, and the
shared floating Back action. Content reserves space above that action. Model
selection and download state remain in the existing scoped model controller.
The actual header and saved preference are covered by
`assistant_settings_hub_test.dart`.

Calendar and Finance product entries open their existing preference editors
directly, matching general Settings: Calendar edits the first day of the week,
and Finance controls amount visibility. Legacy Preferences deep links still
redirect to general Settings. `settings_product_editor_checks.dart` covers
opening each product editor and persisting a choice on the actual Settings host.


### Mobile link browser choice

General Settings offers a device-persisted built-in browser (default) or external
default browser choice for ordinary web links, including assistant Markdown and
model publisher/license links, Mail, Meet chat, Notes and storefront previews.
Authentication, app-update and signed-download flows keep their dedicated
launchers. Mail, phone and SMS links use the system handler. Visible link actions report a localized generic failure without exposing URLs
or platform details, or silently switching browser modes. Initial app-link
opt-outs return a safe failed result when no UI feedback surface is available.
Late settings reads cannot replace a newer read or a saved selection. Helper and settings widget
regressions cover persistence, URL admission, mode selection and retry errors.


### Account notification preferences

Account notification preference reads and writes accept browser cookies and mobile
Bearer sessions. Reads remain scoped to the authenticated user and account rows
(`ws_id IS NULL`); writes derive the actor from the session. This authentication
repair does not establish cross-platform notification delivery or enforcement.
Route regressions cover credential forwarding, anonymous rejection, account
isolation, invalid writes and bodyless HEAD responses. Rust GET already uses
caller-token reads; unported methods continue through the live Next API.

## Stream completion

Native Chat and Mira replies stop reading their NDJSON response after a verified
`done` event. Chat requires a saved message receipt; Mira requires a saved
assistant message receipt. Text or tool deltas alone do not prove persistence.
An explicit server error remains a failed reply even when followed by `done`.
Malformed data before completion and EOF without completion remain errors.
Completed replies ignore post-terminal rows and bytes, and UTF-8 decoding retains
partial characters across transport chunks. Response cancellation starts at
completion; cleanup failures or stalls do not replace the saved receipt or an
earlier transport failure. This applies to native Chat streaming;
legacy Assistant SSE and explicit Live sessions keep their separate protocols.

Regression coverage: `chat_stream_terminal_test.dart` and
`assistant_chat_transport_terminal_test.dart` exercise the real repository and
Assistant cubit with synthetic response bytes, alongside parser and scope tests.
These checks establish source behavior; production provider/storage failures
and actual device transport still require separate runtime evidence.


### Durable assistant receipt and cleanup

After the native Chat/Mira batch RPC returns saved assistant messages, shadow
resource cleanup is supplementary. A thrown cleanup failure cannot remove the
saved JSON/NDJSON receipt or turn an accepted reply into a retry prompt. Failures
before authoritative persistence, including permission or database errors,
remain failures; no text-only success or remote fallback is introduced.
`native-ai-cleanup-receipt.test.ts` covers the actual message route with durable
save followed by failed cleanup. This establishes a source boundary, not the
cause of every missing reply or device/provider delivery evidence.

### Compact on-device status in the header

Native Mira Chat shows on-device readiness, preparation or attention status in
its shared branded header, rather than a repeated block above the conversation.
The accessible control opens full model status and failure guidance with an
explicit model-settings action. It retains a 48px touch target and truncates the
compact label on wide layouts. Narrow action rails fold status into the branded
name control, preserving a readable title prefix and full accessible status. Only
Chat with registered local status uses a 48px header content minimum; default and
other-route geometry stays unchanged, and floating content clearance matches. The current saved assistant
name appears in both Chat and Live; Live hides the local-text chip because voice
uses its separate remote runtime. Returning to remote Chat removes the chip.
Retained recovery actions reject actor/workspace/selection changes and disposal.
No status control sends a failed local prompt remotely or proves native readiness.

`assistant_compact_model_header_test.dart` covers the actual page and header in
English/Vietnamese at 320px with enlarged text, recovery guidance, remote return,
Live visibility and stale actions. `assistant_mode_title_test.dart` preserves
fallback titles and verifies current name changes. Actual-device safe-area,
accessibility and native model loading remain separate delivery checks.
