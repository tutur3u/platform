---
title: "Mira client actions"
description: "How Mira UI tools (theme, panels, navigation) are offered only to clients that can apply them."
---

Some Mira tools change the app rather than workspace data: `set_theme`,
`set_sidebar`, `show_workspace_artifact`, `manage_workspace`,
`set_immersive_mode` and `open_app`. The server returns a success marker and the
client applies the effect. Mira must never report an effect that no client
applies.

## Capability declaration

Each client declares the effects it applies with `clientCapabilities`:

| Capability | Tools |
| --- | --- |
| `theme` | `set_theme` |
| `sidebar` | `set_sidebar` |
| `artifact_panels` | `show_workspace_artifact`, `manage_workspace` |
| `immersive` | `set_immersive_mode` |
| `navigate` | `open_app` |

The server removes undeclared UI tools from the registry, tool discovery and
forced tool steps. When a forced tool is unavailable, the step falls back to
discovery instead of requiring an impossible call. A client that declares
capabilities also gets a short prompt note naming the missing effects. For
example, without `artifact_panels` Mira uses `open_app` or answers in chat.
Unknown capability names are ignored so newer clients stay compatible. Data
tools are never gated by capabilities; permissions still apply.

Defaults by surface:

- Web Mira chat declares `theme`, `sidebar`, `artifact_panels`, `immersive` and
  `navigate`.
- A request to the shared AI chat route without a declaration keeps the legacy
  Web set (everything except `navigate`).
- The native `/chat/conversations/:id/messages` route, used by mobile, forwards
  a declared set. Without a declaration it uses `theme` and `immersive`, which
  is what current mobile builds apply. Mobile no longer gets panel tools it
  silently ignored.
- Canonical Live (`/api/v1/assistant/live/tools/execute`, used by mobile Live)
  defaults to no UI effects. Previously `set_theme` and panel tools reported
  success there without any client effect. A client opts in by sending
  `clientCapabilities` with each execution. The route also resolves the user
  timezone (client value, then saved personal, then workspace preference).
- Web dashboard Live declares `open_app` as a client function, alongside the
  existing theme, sidebar and panel functions.

## `open_app`

`open_app` switches to another app in the current workspace. Destinations:
`home`, `assistant`, `tasks`, `habits`, `calendar`, `finance`, `time_tracker`,
`mail`, `drive`, `meet`, `notes`, `chat`. It only navigates; it does not read or
change data. Each client maps destinations to its own routes. Web uses
`/:wsId/<segment>`, and Web's proxy redirects satellite segments to their owning
app. Web ignores markers with an unknown destination or an unsafe workspace
segment. Web Live navigation leaves the Live page.
