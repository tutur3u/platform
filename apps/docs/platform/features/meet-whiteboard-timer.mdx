With `MEET_UX_V2` on in Meet, the Activities menu offers one **Whiteboard**
("Bảng trắng") and one **Timer** ("Hẹn giờ") instead of several older entries.
With the flag off, and in Parley, the menu is unchanged.

## Whiteboard

**Scope.** The Activities menu, the stage pane title, the minimized-activity
chip in the dock and the phone activity switcher.

**Default.** The Whiteboard entry opens the Tuturuuu Whiteboard (Excalidraw)
linked to the meeting. It is always kept in the workspace whiteboard as people
draw, so nothing in Meet asks anyone to save it and there is no Save button. The
board's host controls (link, create, guest access, remove) are unchanged; see
[Saved whiteboard](/platform/features/meet-calls#saved-whiteboard).

**Who gets which board.** The entry opens the first of these the person may use:

| Order | Older entry | Stage id | Who has it |
| --- | --- | --- | --- |
| 1 | Saved whiteboard | `board` | People who may use the room's tools; anonymous guests only while `MEET_GUEST_WHITEBOARD` is on |
| 2 | Pen whiteboard | `tool:pen-whiteboard` | People who browse the tools, including activity runners in host-only rooms and guests where tools are open to everyone |
| 3 | Classroom whiteboard | `whiteboard` | Rooms with classroom tools |

While `MEET_GUEST_WHITEBOARD` is off, a room with an anonymous guest in it puts
the pen board first for everyone, so the whole room draws on a board the guest
can open. The Tuturuuu Whiteboard stays last in that order, so it still opens
where no pen board is offered.

**Older ids.** Every older id still routes to its own pane, so a saved layout,
a host's default activity, a Follow or a Summon from a client without the flag
still opens the pane, and nothing stored is moved or deleted. Each of those
panes is titled **Whiteboard** with the pen icon.

**Exceptions.**

- Summon has no room view for the Tuturuuu Whiteboard, so it is shared through
  Follow (layout mirroring) only. This is a known limit; the pen board keeps
  Summon.
- Opening the Whiteboard shows the boards linked to the meeting. The host links
  an existing workspace whiteboard or creates one from that picker; nothing is
  created automatically.
- Pen board strokes and classroom whiteboard drawings still end with the room;
  only the Tuturuuu Whiteboard stays after the call.

## Guests on the Tuturuuu Whiteboard

**Switch.** `MEET_GUEST_WHITEBOARD` on the Meet Worker, read by the server like
`MEET_UX_V2`. It is on only for the exact string `true`; the default is off.
It stays off until the security review approves the guest path. If that review
has not approved it by 30 November 2026 18:00 ICT, EduFest runs with it off,
on the pen board.

**Who it covers.** Everyone outside the meeting's workspace: anonymous guests
and signed-in people who are not workspace members. Workspace members and the
host are not affected by the switch.

**On.** A person outside the workspace opens the Tuturuuu Whiteboard from the
Whiteboard entry, or follows a leader onto it, and views or draws as the
link's guest access allows (**No access**, **Can view**, **Can draw**, set by
the host). Co-Programming and the live document still ask a guest to sign in.

**Off.** The whiteboard API refuses everyone outside the workspace (HTTP 403)
before it reads any board, anonymous guests keep the sign-in state on a board
pane, and with `MEET_UX_V2` the Whiteboard falls back to the pen board for
them and for everyone in a room with one of them. Without `MEET_UX_V2` the
board stays listed for signed-in non-members, and opening it reports that the
whiteboard could not be opened.

**What a guest can reach.** Only boards linked to the current meeting whose
guest access is view or draw, in the meeting's workspace, never archived. A
guest never sees the workspace board list, link settings or management
actions, and the board accepts no images or files. Everyone on a board is
named by a per-board id derived from their user id, so nobody sees another
person's platform user id. From people outside the workspace the board keeps
only the drawing fields Excalidraw uses, each checked for type, size and
range: positions within 1,000,000 px, sizes up to 100,000 px, point
coordinates within 100,000 px, stroke widths 0.5 to 64, roughness 0 to 5,
opacity 0 to 100, font sizes 1 to 2048, line heights 0.5 to 10, pressures 0
to 1, binding focus within -1 to 1, bounded text, known styles, at most 32
groups and 256 bound elements. A line, arrow or freehand stroke from someone
outside the workspace holds at most 10,000 points; a longer stroke is refused,
so very long freehand strokes need to be drawn in parts.

Fills are budgeted so no board can freeze the people viewing it. A hachure,
zigzag or cross-hatch fill is estimated as the diagonal of the shape's box
(for lines, arrows and freehand strokes, the larger of their size and their
points' span) over four times the stroke width, counted twice for zigzag and
cross-hatch. A shape without a fill style counts as hachure, and a
transparent background draws no fill. One element from someone outside the
workspace may draw at most 10,000 fill lines, and their edits are refused
once the whole board, members' shapes included, would pass 200,000. Members'
own edits are never refused for fills, and anyone may still shrink or delete
a shape on a full board.

An element with a malformed or out-of-range field is refused and the sender is
told. Links must be http(s) or same-site, with no backslash or
control character; other links are cleared.

**Revocation.** Board tickets for people outside the workspace last one minute
and the call renews them every 30 seconds through the Meet API. Each renewal
asks the room's `board.access` check whether the person has an open connection
to the room right now, and checks again that the switch is on and the board is
still linked with guest access. Waiting, removed and only remembered guests
are refused, and so is someone whose call connection dropped, even while the
room still shows them during its 30-second reconnect grace period. The last
ticket a person received stays valid for at most a minute, so after they
leave, are removed, drop off, or their board is unlinked, archived or set to
no access, they receive board data and can send edits for at most one more
minute. The board room closes the expired connection at its next sweep, at
most a minute after that, without sending it anything in between. Members
keep two-minute tickets.

**Limits.**

- The Meet whiteboard API allows each person outside the workspace 30 list or
  join calls a minute per meeting (HTTP 429 with `Retry-After` beyond that),
  counted in the shared abuse-guard store or, when it is unavailable, per
  isolate.
- People outside the workspace get 20 board messages a second (members 40),
  messages up to 256 KiB (members 1 MB), at most three open board connections
  each and six connection opens a minute each. Guests hold at most 30 of a
  board's 50 connections, so members always find room. A connection over a
  limit is refused or closed; the client reconnects with a fresh ticket. The
  open counts are stored with the board room, so an eviction does not reset
  them (except while `MEET_WHITEBOARD_FLUSH_DISABLED` keeps storage off).
- A board that nobody is connected to reloads from the database for its next
  joiner only if its last load is at least 30 seconds old, so rapid reconnects
  cost no database read. The load time is stored with the board's state and
  survives an eviction.

**Exceptions.** Rules for under-18 and unconfirmed participants and every host
control are unchanged.

## Timer

**Scope.** The Activities menu and the Timer pane or page.

**Default.** One Timer with a **Just me** / **Everyone** switch ("Chỉ mình tôi"
/ "Mọi người"). Hosts and co-hosts who may set the room timer start on
**Everyone**; everyone else starts on **Just me**.

- **Everyone** is the room's class timer with its server rules unchanged: it
  needs `MEET_CLASS_TIMER_ENABLED`, hosts and co-hosts start it, and only the
  host pauses, resumes and stops it. Everyone admitted sees the read-only chip.
- **Just me** is the private countdown on this device. It never writes room
  state and keeps running while hidden.
- People who may not set the room timer see **Everyone** disabled with the
  reason: "Only hosts and co-hosts can set a timer for everyone." or, when the
  room has no shared timer, "This room does not offer a timer for everyone."

**Where it opens.** For people who browse the tools it is the Timer pane
(`tool:timers`). A host or co-host who does not browse the tools (for example in
a host-only room) still gets the Timer as a page in the Activities dialog
(`class-timer`), with the same switch. The older ids keep routing; a `tool:timers`
pane is titled **Timer**.

**Default activity setting.** With `MEET_UX_V2` on, the host's **Open for
everyone who joins** setting names the pen board **Whiteboard** and the
private timer **Timer**. The stored values (`tool:pen-whiteboard`,
`tool:timers`) are unchanged, so a room that already has one keeps it.

## EduFest classes

The EduFest run (guest join, Upskii presenter, Follow, classroom quizzes, Q&A,
transcripts) does not use either activity. With `MEET_UX_V2` on and
`MEET_GUEST_WHITEBOARD` off, a class with guests in it gets the pen board as
its Whiteboard. With both on, guests draw on the Tuturuuu Whiteboard when the
host sets the board's guest access to **Can draw**.
