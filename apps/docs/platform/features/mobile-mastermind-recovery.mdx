---
title: Mobile Mastermind recovery producer
description: Install and operate the read-only recovery summary job.
audience: developers
---

The producer counts unsettled failed and interrupted threads from the local
T3 SQLite projections and the publisher's authenticated T3 peer links. A peer
is counted only after a complete live listing. A failed or incomplete listing,
expired link, or usage-only configured machine gets an unread host slot.
The producer never uses SSH. Missing classification evidence is recorded as
`unknown`. Holds and eligibility grant no retry permission.

The sweep log is optional. Only complete aggregate receipts in the form
`YYYY-MM-DD HH:mm ICT | <action-key>=<count>` within two hours populate
`actions_executed`. The latest receipt per contract key wins. An omitted
action count means there was no accepted receipt. Existing free-form sweep
entries are ignored.

## Install on the publisher host

After operator approval, install the following files from the reviewed revision
into the installed copy in `~/.local/share/fleet-sync/bin/`.

- `recovery-producer.mjs`
- `recovery-summary.mjs`
- `fleet-state.mjs`
- `lane-outcomes.mjs`
- `peer-lanes.mjs`
- `scrub.mjs`

Keep the producer and consumer on the same SOURCE_SHA when enabling unread
host slots.

Create private `recovery/` and `logs/` directories under the fleet-sync root.
Copy `recovery-producer.plist.template` to the user's LaunchAgents directory
as `com.tuturuuu.fleet-recovery-producer.plist`. Substitute the absolute Node
26 executable and fleet-sync root, then check the result with `plutil -lint`.
Bootstrap it in the publisher user's GUI launchd domain after updating the
publisher consumer and the Web recovery contract.

The job runs at load and every five minutes. This is well inside the two-hour
staleness window while keeping peer read volume bounded. A single launchd job
label serializes its invocations. Peer calls share a ten-second per-peer
deadline, and the process watchdog bounds an asynchronous stall to 25 seconds.

The producer fsyncs a mode-0600 temporary file beside `summary.json` and then
renames it. A failure before rename preserves the previous summary and writes
one count-only line to `logs/recovery-producer.log`. Forced termination can
leave an unpublished mode-0600 temporary file, which the publisher ignores.
After bootout, an operator can remove abandoned `.summary-*.tmp` files.

Verify with `node --test scripts/mastermind-fleet/recovery-producer.test.mjs`.
