Every web app (`apps/web` and each satellite sharing `packages/ui`) renders the
same account menu from the avatar in the sidebar footer. This page records the
product rules for its entries.

## Community links

- **Scope:** account menus, sidebar footers, help menus, settings and mobile web
  layouts of every app that renders `SatelliteFooterActions` or
  `AccountHubActionItems`.
- **Default:** Discord links are hidden. `COMMUNITY_LINKS.discord` in
  `packages/ui/src/components/ui/custom/community-links.ts` is the single
  switch; apps keep passing `discordHref`, and the shared publisher and menu
  drop it while the switch is off.
- **Exceptions:** documentation links (for example the SDK docs Discord card)
  are not governed by this switch.
- **Regression coverage:** `satellite-shell.test.tsx` and
  `satellite-user-menu-items.test.tsx` in `packages/ui`.

## Profile

- **Scope:** the account menu's Profile entry in `apps/web`, `apps/workspace`
  and every satellite whose settings dialog uses
  `createAccountSettingsNavGroup` (`packages/satellite`).
- **Default:** Profile opens the Public profile tab
  (`SHARED_SETTINGS_TAB_IDS.publicProfile`) in the current app's settings
  dialog. The tab renders `PublicProfileCard`, the component the
  `/u/[username]` page renders, limited to name, bio, avatar and banner.
- **Address:** when the profile URL shares the page's origin (apps/web on
  tuturuuu.com), the tab replaces the address with `/u/<username>` without
  navigating (`packages/ui/src/hooks/public-profile-address.ts`). The shared
  `useSettingsDialogUrlState` hook keeps the dialog open on that tagged entry.
  Closing, switching tabs or Back restores the previous address. Other origins
  keep `?settingsDialog=open&settingsTab=public_profile`.
- **Deep links:** loading `/u/<username>` renders the full public page; a reload
  while the tab is open does the same.
- **Exceptions:** users without a username see a prompt to choose one in the
  Profile tab. A menu rendered without a settings dialog keeps the link to the
  public page.
- **Regression coverage:** `public-profile-address.test.ts`,
  `use-settings-dialog-url-state.test.tsx` and
  `public-profile-menu-item.test.tsx` in `packages/ui`;
  `public-profile-panel.test.tsx` in `packages/satellite`; the `/u/[username]`
  page test in `apps/web`.

## Upgrade

- **Scope**: the Upgrade entry of the account menu in every app that ships the
  shared sidebar (`SidebarFooterActions`). It is shown only while the workspace
  is on the Free tier.
- **Default**: selecting Upgrade opens the Upgrade dialog on the current page
  instead of navigating to billing. The dialog reuses the settings dialog shell
  and has three tabs: Plans (monthly or yearly cards with a checkout button),
  Compare plans (a table of price, seats and inclusions) and Current plan.
  Its state is in the URL (`?upgradeDialog=open&upgradeTab=plans|compare|current`);
  opening pushes a history entry so Back closes it, and tab changes and closing
  replace it.
- **Data**: `GET /api/v1/workspaces/[wsId]/billing/upgrade-options` returns the
  self-serve plans (one Free plan and the publicly listed Plus and Pro seat
  products), the workspace's active subscription and the pay billing URL. It
  accepts web and satellite app sessions and requires `manage_subscription`;
  other members see a permission message.
- **Checkout**: the dialog does not create checkouts. A plan's button opens
  `<pay>/<wsId>/billing?plan=<productId>` in a new tab, where the pay billing
  page opens its plan list and runs the existing Polar checkout and guarded
  plan-change flows. "View full billing" opens the same page without the hint.
- **Exceptions**: workspaces on a paid tier do not see the entry. Free is never
  offered a checkout button, and plans below the current tier show "Manage in
  billing" instead.
- **Regression coverage**: `upgrade-dialog.test.tsx` (menu entry, plan list,
  current plan marker, checkout handoff, comparison table headers, permission
  state), the route test beside `upgrade-options/route.ts`, and
  `packages/internal-api/src/upgrade-options.test.ts`.

## Feedback

- **Scope:** the Feedback entry of the account menu in every app, and every
  other entry that opens the report-problem flow (the satellite user menu, the
  guidance feedback action in settings, and Colab).
- **Default:** Feedback opens `ReportProblemDialogContent`, which renders
  `FeedbackDialog` inside `SatelliteSettingsDialogShell` with
  `showOnboardingGuide={false}`. The shell supplies the full-screen layout, the
  navigation search, the mobile navigation and the dialog shortcuts. The
  navigation has one group with two sections: "Send feedback" (product, support
  type, description and up to five image or video attachments) and "Your
  feedback" (a receipt per report accepted in the current session). A
  successful submission keeps the dialog open, clears the form and switches to
  "Your feedback".
- **Backend:** submissions still go through `useReportProblem` and
  `useSubmitReportMutation`, which upload attachments with signed URLs and call
  `submitReport` from `@tuturuuu/internal-api/reports`. The receipt id is the
  `reportId` the backend returns. Receipts live in the TanStack Query cache
  under `feedback-receipts` and are not persisted across reloads.
- **Exceptions:** the dialog open state is local to each host and has no URL
  parameter, so Back does not close it. The `/api/v1/product-feedback`
  receipts endpoint is keyed by the idempotency key of a product-feedback
  submission and is not read here.
- **Regression coverage:**
  `packages/ui/src/components/ui/feedback-dialog.test.tsx` covers the dialog
  rendering inside the shell, a submission calling `submitReport` and listing
  its receipt, and the empty "Your feedback" state.
