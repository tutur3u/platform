## Product decision

Decision (25 November 2026). Status: implemented behind `MEET_UX_V2`.

Scope: Meet meetings with `MEET_UX_V2` enabled. Private Mira (voice and the
Tutor chat), room documents, Polls and Co-programming. Parley and meetings
with the flag off keep their existing behaviour.

Default: Mira drafts but never publishes, edits only room documents, suggests
code only as a diff, and reads no tutor chat until its owner turns sharing
on.

Approved access rules:

| Capability | Rule |
| --- | --- |
| Draft polls and action items | Mira drafts; a host or co-host publishes. Nothing posts by itself. |
| Edit docs | Allowed on room-shared docs only; every edit is attributed "Mira for {person}" and can be undone. |
| Suggest code | Mira's suggestions appear as a diff; one person must accept. No direct writes. |
| Read tutor chat | Owner-only opt-in. Each person can share their own tutor chat with their own Private Mira for this meeting (default off, revocable, shown as a chip). A host can never grant access to someone else's private data, and Room Mira never reads private data. Under-18 and unconfirmed accounts: never. |

### How each rule is enforced

- **Polls.** With the flag on, Private Mira voice has no `launch_poll` tool and
  the live worker refuses a `launch_poll` call. Mira's drafts stay drafts until
  someone who manages the room's polls launches them in Polls: the host, or a
  co-host with participant management, which the room checks on `poll.launch`. Action items reach the room only
  through notes review or a document edit, both of which a person approves.
- **Documents.** The room records a Mira edit only for a tab that exists in the
  meeting's shared document set, and only while the requester's Private Mira
  choice is the revision the server checked. Each edit stores the requester's
  account and in-call name; the document panel shows **Mira for {person}**,
  and the host or requester can undo it.
- **Code.** Mira's live answer is saved as a private draft. The host publishes
  it as a proposed diff, and a person (the host, never a Mira service token)
  accepts or dismisses it. The code document changes only on that accept, and
  only when the original lines still match.
- **Shared tutor chat.** The share is a per-meeting grant in the
  room, keyed by the signed-in account. Only that person can turn it on or
  off; the request carries no target account. Turning it on needs a confirmed
  adult Mira account ([one Mira confirmation per account](/platform/features/meet-calls#one-mira-confirmation-per-meet-account))
  and a current Private Mira Continue choice. The room accepts turning a
  share on, reading it and filling it only from a server-issued token without
  the live scope, so a browser call token cannot skip those checks; revoking
  stays open to the owner. While it is on, the server passes the owner's
  latest tutor chat (up to 12 turns, about 15 KB) to the room after each Tutor
  answer, in the background so the answer never waits for it. With sharing
  off, no forward happens. Only a Private Mira voice session registered to
  that same person, on a token carrying the private scope, can read it, and
  the live worker checks the workspace gate and the account confirmation
  again before every read. Room Mira sessions never carry that scope.
- **Where shared tutor chat is kept.** Each person's shared chat lives under
  its own key in the room's Durable Object storage. The room snapshot keeps
  only small metadata (when it was shared and its size), so a busy room never
  rewrites everyone's chat on each write. One person's chat is capped at
  16 KB, and all shared chat in a room at 256 KB: a new share evicts the
  oldest shared chats until it fits. The stored chat counts only while it
  matches the grant revision and share time in the snapshot.

### Revoke and lifetime

- The chip **Shared with your Private Mira** shows while sharing is on; its
  close button revokes in one tap. The Private Mira panel's info popover has
  the same switch.
- Revoking deletes the shared tutor chat and refuses the next read. It never
  needs an account confirmation.
- Revoking also ends the owner's Private Mira voice sessions, so nothing a
  session already read stays in a live model conversation. The room returns
  every session registered to the owner with the revoke, so this works after
  they left the call. If a session cannot be stopped, the revoke still
  applies to future reads and the request reports the failure; trying again
  stops it.
- Withdrawing the Mira account confirmation revokes the share and ends the
  owner's Private Mira sessions. In a call, the room revoke returns the
  sessions to stop. From account settings, the owner's session registry stops
  each live Private Mira session and then revokes its meeting's share; the
  sessions run in parallel, each step has its own deadline, and a session
  that could not be stopped stays listed for a retry. Both paths are best
  effort and bounded; every later read also needs a confirmed account, which
  a live worker may have cached for up to a minute.
- A share counts only if it was turned on after the owner's latest Mira
  confirmation. Withdrawing and confirming again therefore needs a fresh
  opt-in, even for a share in a meeting that had no live Private Mira
  session. The room reports when each share was turned on; the server and
  the live worker compare that with the confirmation time, revoke an older
  share, and treat it as off. A share without a known start, or an account
  without a confirmation, fails closed.
- Changing the Private Mira choice (Mute or Leave, then Continue again) ends
  the share and drops its shared tutor chat; the share does not come back on
  by itself.
- Shared tutor chat expires one hour after the owner last sent it. An expired
  read returns nothing. The room sets its alarm for the earliest expiry and
  deletes expired chat on that alarm or on any earlier write, even when no
  further requests arrive. Every share and its stored chat is removed when
  the meeting ends or is restored, and a subject or meeting erasure removes
  the subject's share (or every share).

### Intentional exceptions

- Meet does not yet have a separate private notes surface, so today the share
  carries the Tutor chat only. A future private notes surface must use the
  same grant.
- With the flag off, the permissions card keeps showing **Read private notes
  or tutor chats: Blocked** and Private Mira keeps its original poll tools.
- Private Mira poll tools remain available to the meeting host only.
- A workspace admin who joins someone else's meeting as a co-host without
  participant management cannot launch polls; the room's existing poll rule
  applies.

### EduFest classroom flow

Guest join and classroom activities do not change. Guests cannot turn sharing
on, and Private Mira's poll launch moves to the Polls panel for the host.
