title: Native mobile Timer
description: Session controls, task links, and tracking history in the shared mobile shell.
---

Mobile Timer keeps Start, Pause, Resume, and Stop in the existing shell-owned
floating action surface. The page does not mount another floating bar. Available
controls follow the current session; while a control is awaiting completion,
other session controls are disabled to prevent repeated taps.

The missed-entry action uses the same shell action registration on Timer,
History, and Statistics, instead of a separate floating button. It remains
available only with an authenticated workspace context. On narrow screens,
secondary actions can move to the shared header overflow rather than clipping.
Existing threshold approval, category selection, task links, and tracked-session
history keep their established behavior.

The clock scales down to fit narrow layouts and enlarged text. Pomodoro phase
and running/paused/stopped labels use the app locale. Scroll content includes
the shell-provided bottom inset so session details remain reachable above the
dock. This presentation does not change billing, offline replay, or server
tracking semantics.

Regression coverage: `timer_native_controls_test.dart` checks state-dependent
shell registrations, disabled in-flight controls, route disposal, a long-running
clock under enlarged text, and Vietnamese Pomodoro labels. Actual native
session timing and dock transition smoothness require device verification;
widget tests do not establish either.


## Shared Pomodoro preparation is inactive

The private time-tracker control foundation prepares actor/workspace-scoped
configuration only. Its schema requires `mode=off`, `phase=idle`, and no deadline;
its service-only RPCs initialize, read, and update configuration with revision
checks. Browser roles cannot read, write, or execute those RPCs. Configuration
contains positive integer minute durations up to 180 and a cycle length up to
24, with explicit boolean automation choices. These are foundation storage
bounds, not a change to the current mobile or web controls.

A repeated latest command with identical input returns its existing revision;
a stale revision or reused command with different input fails. An optional
prepared-session reference must belong to the same actor and workspace. It is
an inert reference, not a live session binding: existing session deletion stays
possible. The foundation changes no tracked work, breaks, approval policy,
client timer, settings preference, notification delivery, or scheduler.

Activation requires a later reviewed contract that normalizes Web, Track,
quick-start, AI, direct-write and approval lifecycle paths under the same lock
order and atomically updates phase and existing tracker accounting. This
foundation is a prerequisite and does not deliver cross-platform Pomodoro or
completion while every client is closed.

The `time-tracker-control-contract.yaml` workflow checks out the exact source,
replays the complete schema in the repository-owned isolated lifecycle, runs
`time-tracker-control.sql` with strict TAP validation, and runs actual concurrent
configuration-CAS and command-replay races. It then generates actual public
schema types as an exact-SHA artifact and requires owned lifecycle cleanup.
No generated type file is hand-edited. The new private preparation objects do
not imply new public API types.

Focused runner tests can run through `ttr resources run -- node --test
apps/database/scripts/time-tracker-control-contract.test.mjs
apps/database/scripts/programming-database-tap.test.mjs`. The full SQL verifier
starts a disposable database and belongs in exact-head CI or an explicitly
admitted host; it must not be run under a no-local-setup restriction. Local
script tests alone are not schema, SQL concurrency, device, or production proof.

### Unwired OFF-only replacement boundary

A private service-only operation can atomically close the expected running
session and start its replacement while the existing control is OFF and idle.
No mobile, web, quick-start or AI caller uses it. It carries a separate operation
revision and retained input-bound command receipt; configuration revision is
unchanged. A receipt reports its **applied** result, including an older replay,
and does not claim to describe the latest session.

The operation acquires the existing actor/workspace advisory key before control,
linked requests, session and break rows. One database timestamp captured after
contention closes and starts work. Existing accounting and policy triggers remain
in force; a future-starting running row is rejected without work credit. Any
failure rolls back session writes, operation revision and receipt. Browser roles
cannot call the operation, and even the service role cannot directly mutate its
private bookkeeping tables.

Full-schema catalog assertions retain an explicit baseline of legacy writers,
RLS policies, triggers and FK actions, including the task-workspace guard and
approval activity/notification effects. Unexpected drift fails validation. This
baseline intentionally leaves writer closure **open**: the new operation cannot
become authoritative until legacy direct writes, bypass RPCs and every lifecycle
caller use a consistent boundary. CI executes real pgTAP and two-connection CAS,
replay and shared-scope contention tests with actual type generation and cleanup.

Shared phase/settings, pause/resume/skip, deadline reconciliation, cross-client
realtime and background notification behavior remain separate prerequisites.
This unwired boundary provides no all-clients-closed completion or device proof.
