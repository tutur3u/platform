# Web Start candidate slices

Keep migration adapters in `apps/web/cloudflare`; the retired
`apps/tanstack-web` runtime remains paused. Read the
[owning runbook](../../../../../apps/docs/build/devops/web-start-candidate.mdx)
for native route scope, staging inputs, rollback and release prerequisites.

Public legal documents reuse `@tuturuuu/legal` through a React/Start adapter.
Do not pull inherited Next marketing layouts, request globals or session
resolution into the portable legal package. Preserve every canonical section
and review notice in EN and VI.

Keep document admission separate from whole-candidate admission. Unknown or
unset slice flags fall back to attested Next; disabling the candidate returns
503. RSC/action traffic, APIs, satellite sessions and the service worker retain
their Next owners.

Run source tests, candidate types, emitted workerd tests and acceptance-policy
tests. A default Start streaming response can include serialization scripts even
without a Scripts component: verify actual emitted HTML when promising a
script-free document. This slice uses Start's static HTML callback and ordinary
browser links. Resource admission and the current host restrictions still apply.

The staging acceptance suite blocks production before browser startup and
fences network requests. Extend the shared suite; distinguish local synthetic
Worker acceptance from hosted EN/VI authentication and exact-source evidence.
Do not provision resources or enable any flag as part of source qualification.

Keep hosted Playwright cases out of the ordinary Web Vitest discovery; run
their host policy under Node and their browser cases through the staging-only
Playwright config. Resolve test fixture paths with node:path and fileURLToPath,
so Vite does not rewrite new URL asset expressions to an HTTP URL under jsdom.
