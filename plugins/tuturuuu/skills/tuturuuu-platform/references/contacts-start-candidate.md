# Contacts default-off candidate

Use the canonical [runbook](../../../../../apps/docs/build/devops/contacts-start-candidate.mdx)
for owner inputs, acceptance commands, cost/stop bounds and release evidence.
Contacts is the Easy Center tutoring surface. Its staging-only Worker is additive;
only the inert `/__contacts1` probe is native, and all customer/API requests retain
Contacts Next fallback. Do not route `/api/*` straight to central Web: that would
bypass Contacts-owned feedback, payments and app-session handlers.

Generate the full Contacts route manifest with `routes:candidate` and retain the
first-party boundary census separately with `--artifact <private-path>`.
Candidate tests cover actual forwarding and the existing portable Contacts session
core. The without-fix control removes admission and fallback dispatch independently,
requires assertion failures, restores source and reruns green. Policy tests reject
production hosts before Playwright launch. EN/VI hosted checks use unprefixed
Contacts routes and `NEXT_LOCALE`, matching `localePrefix: never`.

No hosted PASS follows from fixtures or a build. Keep immutable fallback ownership,
staging cookie/issuer adapters, upstream project attestation, distinct staging-only
origin-proof key, exact emitted Worker source and customer tutoring/editor flows as
explicit release prerequisites. Do not add providers, DNS, routes or credentials
as part of candidate scaffolding.
